6The Atomic MigrationCommand

What it does

  1. Acquire per-key read/write lock (blocks concurrent ops on K).
  2. Send MigrateBatch to target; target writes K only if it does not already exist (insert-if-absent), then acks.
  3. Delete local copy of K.
  4. Release lock once the command passes CPL. Command is persisted, so it resumes after restart.

Key point — order is everything: the local delete only happens after the target acks the MigrateBatch. Because CPL runs ahead of EAL, a source read that finds the key absent must wait not just for commit but for EAL apply before replying MIGRATED_ROUTE — guaranteeing the key is already persisted at the target and never falls into a "nowhere" gap. See R10.

Why it's safe

  • Export + delete are atomic for a key — no window where K exists in both or neither place servicing writes.
  • Persisted in the Raft log → survives leader change / rollout.
  • Idempotent — a re-sent MigrateBatch after a lost response is insert-if-absent, so it never corrupts state or overwrites a newer client value.
  • Target accepts MigrateBatch under its old route, keyed by IMPORTING label.
